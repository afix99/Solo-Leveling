# ASCEND — Discipline Leveling System (Android App)

**Status:** Approved
**Date:** 2026-08-06

## 1. Summary

A native Android app that fuses a discipline/habit journal (daily non-negotiables,
streaks, weekly review, an "excuses vs truths" reframe) with a Solo Leveling–style
RPG progression system (per-category stats, XP, Hunter Level, Rank E→S, and a real
penalty system for missed non-negotiables). Fully offline, single-user, no login,
no backend. Delivered as a real installable `.apk`.

Inspiration: user's own discipline-journal photos (daily non-negotiables checklist,
30-day habit tracker, weekly progress/reflections, "30 Lies I Told Myself" reframe
list) combined with the Solo Leveling manhwa's "System" status-window aesthetic and
level-up/rank-up mechanic.

## 2. Tech Stack

- **Language/UI:** Kotlin, Jetpack Compose (Material 3, custom themed — not stock
  Material look)
- **Local storage:** Room (SQLite) — all data on-device, nothing leaves the phone
- **Background work:** WorkManager — daily local notifications, midnight
  rollover/penalty evaluation
- **Build:** Gradle (Kotlin DSL), Android SDK command-line tools fetched at build
  time in this environment
- **Min/target SDK:** minSdk 26 (Android 8.0+), targetSdk latest stable
- **Output:** `app-release.apk` (debug-signed, sideload-ready — not a Play Store
  submission), sent to the user as a file plus pushed to the repo

## 3. Data Model

### Stat (fixed enum, 5 values)
`STR` (physical/body), `VIT` (health/maintenance), `INT` (learning/deep work),
`PER` (mindfulness/awareness), `AGI` (momentum/consistency)

### Habit
- id, name, assigned `Stat`, `isNonNegotiable: Boolean`, reminder time (optional),
  `createdAt`, `archived: Boolean`
- User-created only (no preloaded habit list) — creation flow suggests a default
  stat from keyword matching but user can override

### DailyLog
- One row per (habit, date): `completed: Boolean`, `xpAwarded: Int`,
  `isPenaltyQuest: Boolean` (true if this entry is a redemption task generated by
  a prior miss)

### StatProgress
- Per-stat cumulative XP + derived level (level = f(xp), simple curve — see §4)

### HunterProfile (singleton row)
- hunterName, totalXp, derived overall Level, derived Rank (E/D/C/B/A/S),
  notification times, onboarding-complete flag

### LieTruth
- id, `lieText`, `truthText`, `active: Boolean` (user can retire ones they've
  overcome), `createdAt`

### WeeklyReview (generated, cached)
- weekStart/weekEnd, completionPercent, xpByStat, bestDay, worstDay,
  userReflectionNote (free text, editable)

## 4. Leveling & Penalty Mechanics

- **XP per completion:** non-negotiables award more XP than optional habits
  (e.g. 20 XP vs 10 XP flat, deliberately simple — no streak multiplier
  complexity in v1).
- **Stat level curve:** `level = floor(sqrt(xp / 50)) + 1` (simple, monotonic,
  diminishing — no need for a lookup table).
- **Hunter Level:** derived from sum of all stat XP using the same curve
  formula, scaled up (so overall level rises slower than individual stats).
- **Rank thresholds (Hunter Level):** E: 1–4, D: 5–9, C: 10–19, B: 20–34,
  A: 35–54, S: 55+. Crossing a rank boundary triggers the full-screen rank-up
  animation; crossing any stat level triggers a smaller level-up toast.
- **Penalty on missed non-negotiable** (evaluated at local midnight via
  WorkManager for any non-negotiable left unchecked that day):
  - That habit's stat loses XP (flat penalty, e.g. -15), floored at the XP
    required for the stat's *current* level (can't drop below the level
    already earned).
  - A Penalty Quest is created for the next day: same habit, flagged
    `isPenaltyQuest = true`, pinned at top of Today in amber, worth 1.5x normal
    XP if completed. If also missed, the penalty XP loss repeats but the
    Penalty Quest does not re-stack indefinitely — cap at 1 active penalty
    quest per habit at a time.
- **Streaks:** tracked independently per habit (consecutive completed days),
  reset to 0 on a miss, shown on the habit's detail view — separate from XP so
  a bad day dents XP without erasing a long streak's visible history.

## 5. Screens

1. **Onboarding** — hunter name entry, brief explainer of stats/ranks, create
   first few habits.
2. **Today (Home)** — Hunter Level/Rank badge + XP ring at top; Penalty Quests
   (if any) pinned first in amber; Non-Negotiables checklist; Other Habits
   checklist; occasional Lie/Truth nudge card late in the day if
   non-negotiables remain unchecked.
3. **Stats** — 5 stat cards (level, XP bar, short trend); tap through to a
   per-stat history list.
4. **Habits** — list/create/edit/archive habits; assign stat, toggle
   non-negotiable, set optional reminder time.
5. **Weekly Review** — auto-generated report (completion %, XP by stat,
   best/worst day, streak notes) + editable reflection text box; list of past
   weeks.
6. **Lies vs Truths** — CRUD list of excuse → truth pairs; toggle active/retired.
7. **Profile/Settings** — hunter name, notification times, data export
   (local JSON) and reset.

## 6. Visual Design

- **Theme:** dark "System Window" aesthetic — background `#0A0B0F`, surface
  `#14161D`, primary accent electric blue `#4C8DFF`, secondary accent violet
  `#8B5CF6` reserved for rank-up/legendary moments, amber `#F5A623` for
  penalties/warnings, off-white text `#F2F3F5`.
- **Typography:** Inter or Manrope (bundled), wide letter-spacing on labels/
  headers, large numerals for level/XP — Apple-Health-like restraint despite
  the dark game palette. No neon clutter, generous whitespace, soft
  glass-blur cards (subtle, not skeuomorphic).
- **Signature moment:** level-up = small animated toast/pulse. Rank-up = brief
  full-screen animated overlay (glow pulse, scale/fade motion) — the
  emotional payoff beat that sells the "Solo Leveling System" feel.
- Single dark theme only in v1 (not light/dark switching) — matches the
  approved "dark System window, Apple-clean execution" direction.

## 7. Notifications

Two local daily notifications via WorkManager, no network involved:
- Morning: lists today's non-negotiables.
- Evening: nudge, only fires if non-negotiables remain unchecked.
Both times configurable in Settings; can be disabled entirely.

## 8. Out of Scope (v1)

- No accounts, sync, or backend of any kind.
- No light mode / theme switching.
- No social/sharing/leaderboard features.
- No Play Store publishing — sideload APK only.
- No preloaded habit list — user builds their own from an empty state.

## 9. Delivery

Build produces `app-release.apk` in this repo; file is sent directly to the
user, source pushed to branch `claude/discipline-leveling-android-app-x39jly`.
Install requires enabling "install unknown apps" for the transferring app on
the user's Android device (standard sideload flow) — noted in the handoff
message.
